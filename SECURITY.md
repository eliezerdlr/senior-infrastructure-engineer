# Security Policy

## Supported version

Security fixes are applied to the latest release.

## Reporting

Do not open a public issue containing credentials, customer data, private topology, exploitable operational details, or undisclosed vulnerabilities. Use GitHub private vulnerability reporting when enabled by the repository owner.

Include the affected path/version, trust boundary, reproduction conditions, impact, and a safe validation approach. Do not test against systems you do not own or lack explicit authorization to assess.

## Operational security

This repository contains instructions and offline validation utilities. It does not provide credentials, infrastructure access, production authorization, or an OS sandbox. Treat generated commands and plans as proposals until reviewed for the exact target and version.
